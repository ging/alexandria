# 1. Authoring & Compiling Your First Profile (`alexandriac`)

Hand-maintaining SHACL shapes, JSON-LD contexts, and JSON Schemas separately almost always ends in semantic drift between gates. Instead, in Alexandria you write **one readable YAML bundle** in `alexandria.profiles/v1`, and **`alexandriac`** compiles all artifacts deterministically.

Let's start our **GreenCity Mobility (`mobility`)** story right here! We want partner apps to negotiate fleet telemetry contracts using:
- A domain action **`mob:shareTelemetry`** (specializing standard `odrl:use`).
- A custom policy constraint left operand **`mob:region`** (for geographic restrictions such as `EU` or `ES`).
- Adopted temporal constraints via standard **`odrl:dateTime`** (`lt`, `lteq`, `gt`, `gteq`, `eq`).

---

<Steps>

### Build the `alexandriac` compiler

From the repository root:

```bash
go build -o bin/alexandriac ./cmd/alexandriac
```

### Write the `mobility-v1.0.0.yaml` bundle

Create `/tmp/mobility-v1.0.0.yaml` containing two YAML documents separated by `---`: an **`OdrlProfile`** defining our vocabulary terms, and a **`SpaceProfile`** binding it to validation gates (`policy_intake`) and lifecycle rules:

```bash
cat << 'EOF' > /tmp/mobility-v1.0.0.yaml
dsl: alexandria.profiles/v1
kind: OdrlProfile
profile:
  id: https://mobility.example/odrl/profile/mobility
  version: 1.0.0
  title: { en: GreenCity Mobility Policy Profile }
  publisher: GreenCity Mobility Authority
  license: https://creativecommons.org/licenses/by/4.0/
  base_url: https://mobility.example/odrl/profile/mobility
namespaces:
  mob: https://mobility.example/ns/
adopted:
  left_operands:
    - term: odrl:dateTime
      signature:
        datatype: xsd:dateTime
        operators: [eq, lt, lteq, gt, gteq]
terms:
  - id: shareTelemetry
    kind: action
    included_in: odrl:use
    label: { en: Share Telemetry }
    definition: { en: Access and stream real-time fleet telemetry datasets. }
  - id: region
    kind: left_operand
    label: { en: Authorized Region }
    definition: { en: Geographic zone where telemetry may be processed. }
    signature:
      datatype: xsd:string
      operators: [eq, isAnyOf]
---
dsl: alexandria.profiles/v1
kind: SpaceProfile
space:
  id: https://mobility.example/spaces/mobility
  version: 1.0.0
  title: { en: GreenCity Mobility Dataspace }
  operator: https://mobility.example/party/authority
  base_url: https://mobility.example/spaces/mobility
lifecycle:
  grace_window: P30D
  freshness:
    ttl: PT24H
    max_staleness: P7D
  degraded:
    policy_intake: continue
    dsp_message: continue
bindings:
  - slot: odrl
    profile: https://mobility.example/odrl/profile/mobility
    source: internal
    version: "=1.0.0"
    obligation: mandatory
    conformance:
      - { role: json-schema, applies_to: policy_intake }
      - { role: shacl, applies_to: policy_intake }
  - slot: dsp
    profile: https://w3id.org/dspace/2025/1
    source: vendored
    version: "=2025-1"
    obligation: mandatory
    conformance:
      - { role: json-schema, applies_to: dsp_message }
EOF
```

### Validate `N1`–`N5` rules and compile

Run `alexandriac validate` and `alexandriac compile`:

```bash
./bin/alexandriac validate -vendor deploy/vendor /tmp/mobility-v1.0.0.yaml
./bin/alexandriac compile -vendor deploy/vendor -o /tmp/mobility-out /tmp/mobility-v1.0.0.yaml
```

You should see:

```text
ok: 2 documents valid
/tmp/mobility-out/profiles/odrl/mobility/1.0.0/context.jsonld
/tmp/mobility-out/profiles/odrl/mobility/1.0.0/prof.ttl
/tmp/mobility-out/profiles/odrl/mobility/1.0.0/schema.json
/tmp/mobility-out/profiles/odrl/mobility/1.0.0/shapes.ttl
/tmp/mobility-out/profiles/odrl/mobility/1.0.0/spec.html
/tmp/mobility-out/profiles/odrl/mobility/1.0.0/vocab.ttl
/tmp/mobility-out/space/prof.ttl
/tmp/mobility-out/space/shacl-union.ttl
/tmp/mobility-out/space/space-lock.json
/tmp/mobility-out/space/spec.html
```

<Callout type="info">
Notice how **`schema.json`** and **`shapes.ttl`** accept **both** RDF typed date/time literals (`{"@value": "2023-12-31T06:00Z", "@type": "http://www.w3.org/2001/XMLSchema#dateTime"}`) **and** compact DSP 2025-1 ISO-8601 strings (`"2023-12-31T06:00Z"`) whenever a constraint binds a typed temporal signature such as `odrl:dateTime`!
</Callout>

### Inspect `space-lock.json`

Check `/tmp/mobility-out/space/space-lock.json` to see how `alexandriac` locks exact versions, SHA-256 digests, and gate assignments without relying on any runtime network fetches:

```bash
cat /tmp/mobility-out/space/space-lock.json
```

### Catch an invalid breaking transition (`N4` validation)

What happens later if someone tries to jump directly from active `shareTelemetry` (in `1.0.0`) to `status: retired` in `2.0.0` without passing through a `deprecated` step first? Let's test `alexandriac`:

```bash
sed 's/version: 1.0.0/version: 2.0.0/g; s/"=1.0.0"/"=2.0.0"/g; s/kind: action/kind: action\n    status: retired/' \
  /tmp/mobility-v1.0.0.yaml > /tmp/mobility-bad-v2.yaml

./bin/alexandriac validate -previous /tmp/mobility-v1.0.0.yaml /tmp/mobility-bad-v2.yaml
```

The compiler catches the violation immediately (`exit 1`):

```text
error TERM_RETIRED_WITHOUT_DEPRECATION mobility-bad-v2.yaml#1:19 /terms/0 term "shareTelemetry" was active in 1.0.0 and is retired in 2.0.0 without an intermediate deprecated release
```

In **[Tutorial 4](./04-breaking-changes-and-f6)**, we'll satisfy `N4` properly by adding the intermediate `1.1.0` `OdrlProfile` marking `shareTelemetry` as `deprecated` before retiring it in `2.0.0`!
