# 2. Hub Governance & Authoring Lifecycle

In **[Tutorial 1](./01-first-profile-dsl)** we validated and compiled `mobility-v1.0.0.yaml` locally. Now let's put it on **`alexandria-server`**, the central Vocabulary Hub (`C-HUB`), so every GreenCity participant can discover and verify it safely.

We'll walk through **two super-clear flows**:
- **Flow 1** — Bootstrap the `mobility` namespace (`ana · admin`), copy the Hub DID, appoint steward `sergio`, and upload `mobility-vocab`.
- **Flow 2** — Author, validate (`N1–N5`), propose, review, approve `1.0.0`, and explore immutable `/pub` outputs.

*(Both the **Console UI** with video walkthroughs and equivalent **`curl` commands** are shown side by side below!)*

---

## Flow 1 — Bootstrap `mobility`, Appoint Steward & Upload Vocabulary

<Steps>

### Sign in as `ana` and create the `mobility` namespace

Only a hub administrator (`vhub-admin`) can create namespaces and manage stewards. Note that admins **cannot** mutate namespace contents unless explicitly assigned as a steward too—clean separation of duties!

<Tabs items={['Console UI', 'CLI / curl']}>
<Tab value="Console UI">

1. Open **Identity** (`Anonymous` top right) → **Sign in with OIDC** → click **`ana · admin`**.
2. In **Namespaces**, click **New namespace**, set slug **`mobility`** and title **`GreenCity Mobility`**, then click **Create namespace**.
3. The hub jumps straight to **Overview**. Copy the **Hub DID** badge (you'll paste it into `alexandria-client` next!) and click **Assign steward** → subject **`sergio`**.

</Tab>
<Tab value="CLI / curl">

```bash
export HUB=https://127.0.0.1:8443
ADMIN=$(./bin/fake-idp token --sub ana --roles vhub-admin)

# Create namespace
curl -k -s -X POST "$HUB/v1/namespaces" \
  -H "Authorization: Bearer $ADMIN" \
  -H "Content-Type: application/json" \
  -d '{"slug":"mobility","title":"GreenCity Mobility"}'

# Appoint steward sergio (using your fake-idp issuer)
curl -k -s -X PUT "$HUB/v1/namespaces/mobility/stewards/sergio" \
  -H "Authorization: Bearer $ADMIN" \
  -H "Content-Type: application/json" \
  -d '{"iss":"http://127.0.0.1:9400","sub":"sergio","label":"Sergio — Mobility Steward"}'
```

</Tab>
</Tabs>

### Switch to `sergio` and upload `mobility-vocab`

Create `/tmp/mobility-vocab.ttl`:

```turtle
@prefix mob:  <https://mobility.example/ns/> .
@prefix odrl: <http://www.w3.org/ns/odrl/2/> .
@prefix rdfs: <http://www.w3.org/2000/01/rdf-schema#> .
@prefix skos: <http://www.w3.org/2004/02/skos/core#> .

mob:shareTelemetry a odrl:Action ;
  odrl:includedIn odrl:use ;
  rdfs:label "Share Telemetry"@en ;
  skos:definition "Access and stream real-time fleet telemetry datasets."@en .

mob:region a odrl:LeftOperand ;
  rdfs:label "Authorized Region"@en ;
  skos:definition "Geographic zone where telemetry may be processed (e.g. EU, ES)."@en .
```

<Tabs items={['Console UI', 'CLI / curl']}>
<Tab value="Console UI">

1. Switch **Identity** → **Sign in with OIDC** → **`sergio · steward`**.
2. Open **Vocabularies** (`g v`) → **Register vocabulary** → name **`mobility-vocab`** (`hosted`, `text/turtle`).
3. Click **`mobility-vocab`**, click **Upload content**, paste `/tmp/mobility-vocab.ttl`, and click **Publish revision**.

</Tab>
<Tab value="CLI / curl">

```bash
STEWARD=$(./bin/fake-idp token --sub sergio)

# Register vocabulary
curl -k -s -X POST "$HUB/v1/namespaces/mobility/vocabularies" \
  -H "Authorization: Bearer $STEWARD" \
  -H "Content-Type: application/json" \
  -d '{"name":"mobility-vocab","kind":"hosted","media_type":"text/turtle"}'

# Upload revision 1
curl -k -i -X PUT "$HUB/v1/namespaces/mobility/vocabularies/mobility-vocab/content" \
  -H "Authorization: Bearer $STEWARD" \
  -H "Content-Type: text/turtle" \
  --data-binary @/tmp/mobility-vocab.ttl
```

</Tab>
</Tabs>

Your Turtle vocabulary is now immutable at `/pub/mobility/vocab/mobility-vocab/r/1`, with `/pub/mobility/vocab/mobility-vocab` issuing a `303` redirect to the latest revision.

</Steps>

## Flow 2 — Authoring Studio, Candidate Review & Initial Release `1.0.0`

Now let's bring `/tmp/mobility-v1.0.0.yaml` through the full **draft → validate → propose → approve** workflow and inspect the published artifacts!

<FlowVideo
  src="/videos/flow-02-authoring-release.mp4"
  title="Flow 2 · Authoring Studio (Code ↔ Split ↔ Form), N1–N5 validation, Propose, Approve 1.0.0 & /pub"
  caption="Creating the v1.0.0 draft inline, switching between Code and Split Studio views, validating, proposing, approving 1.0.0, and inspecting /hub/pub."
/>

<Steps>

### Create and validate the `1.0.0` draft

<Tabs items={['Console UI', 'CLI / curl']}>
<Tab value="Console UI">

1. Go to **Authoring** (`g a`) and press **`n`** (or click **New draft**) to open the full-height studio.
2. Notice **Form**, **Split**, and **Code** (`f` / `s` / `y`) stay live-synchronized! Switch to **Code**, paste `/tmp/mobility-v1.0.0.yaml`, then switch back to **Split** and toggle **ODRL Profile ↔ Space Profile** (`1` / `2`) to review your structured forms.
3. Click **Create draft** (or `⌘↵`), then click **Validate** to verify all `N1`–`N5` rules pass cleanly.

</Tab>
<Tab value="CLI / curl">

```bash
# Wrap /tmp/mobility-v1.0.0.yaml in JSON {"content": ...}
jq -Rs '{content: .}' /tmp/mobility-v1.0.0.yaml > /tmp/draft-payload.json

DRAFT=$(curl -k -s -X POST "$HUB/v1/namespaces/mobility/drafts" \
  -H "Authorization: Bearer $STEWARD" \
  -H "Content-Type: application/json" \
  --data-binary @/tmp/draft-payload.json | jq -r '.id | split("/")[-1]')

# Run dry-run validation (no state change)
curl -k -s -X POST "$HUB/v1/namespaces/mobility/drafts/$DRAFT:validate" \
  -H "Authorization: Bearer $STEWARD"
```

</Tab>
</Tabs>

### Propose candidate, inspect compiled artifacts & approve `1.0.0`

When you click **Propose** (`POST …:propose`), the server compiles the entire bundle into an **immutable candidate** so reviewers can inspect every generated file (`context.jsonld`, `schema.json`, `shapes.ttl`, rendered `spec.html`) and the diff against head **before** approving.

<Tabs items={['Console UI', 'CLI / curl']}>
<Tab value="Console UI">

1. Click **Propose** to freeze the candidate.
2. Browse the **Summary** tab (planned dates + diff) and open the **Files** tab to inspect any compiled artifact inline—including rendered **`spec.html`**.
3. Click **Approve & publish** (`1.0.0` is class **`initial`**, so `new_content_from` and `enforced_from` both start **immediately at publication time**!).
4. Open **Versions** (`g l`) and **Publication** (`g p`) to browse the immutable `/pub/mobility/1.0.0/…` tree.

</Tab>
<Tab value="CLI / curl">

```bash
CANDIDATE=$(curl -k -s -X POST "$HUB/v1/namespaces/mobility/drafts/$DRAFT:propose" \
  -H "Authorization: Bearer $STEWARD" | jq -r '.id | split("/")[-1]')

# Optional: inspect candidate files list & diff before approving
curl -k -s "$HUB/v1/namespaces/mobility/candidates/$CANDIDATE/files" \
  -H "Authorization: Bearer $STEWARD" | jq '.[].path'

# Approve 1.0.0 (initial release enters force immediately)
curl -k -s -X POST "$HUB/v1/namespaces/mobility/candidates/$CANDIDATE:approve" \
  -H "Authorization: Bearer $STEWARD" \
  -H "Content-Type: application/json" -d '{}'

# Verify /v1/namespaces/mobility/versions and public /pub/mobility redirect
curl -k -s "$HUB/v1/namespaces/mobility/versions" | jq '.credentialSubject.versions'
curl -k -i "$HUB/pub/mobility"
```

</Tab>
</Tabs>

<Callout type="info">
Notice what makes **`1.0.0` (`initial`)** special: unlike `compatible` and `breaking` updates—which honor a propagation window—the very first version enters force **immediately (`new_content_from = enforced_from = P`)**. So as soon as your sidecar syncs, it becomes **Ready (`Active`)** right away!
</Callout>

</Steps>
