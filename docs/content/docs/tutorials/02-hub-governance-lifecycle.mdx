# 2. Governing a Release

You will publish version `1.0.0` of a namespace. The laboratory of the [quickstart](../getting-started/quickstart) must be running.

```bash
HUB=https://127.0.0.1:8443
ADMIN=$(./bin/fake-idp token --sub ana --admin --ttl 24h)
STEWARD=$(./bin/fake-idp token --sub sergio --ttl 24h)
```

`curl -k` accepts the laboratory certificate.

<Steps>

### 1. Create the namespace and its steward

Only the admin may do this:

```bash
curl -k -X POST $HUB/v1/namespaces -H "Authorization: Bearer $ADMIN" \
  -d '{"slug":"demo","title":"Demo data space"}'

curl -k -X POST $HUB/v1/namespaces/demo/stewards -H "Authorization: Bearer $ADMIN" \
  -d '{"iss":"http://127.0.0.1:9400","sub":"sergio","label":"Sergio"}'
```

From here on every operation uses the steward token. The admin token would be answered `403`: being admin does not grant namespace operations.

### 2. Register vocabularies

A hosted vocabulary, with content you upload:

```bash
curl -k -X POST $HUB/v1/namespaces/demo/vocabularies -H "Authorization: Bearer $STEWARD" \
  -d '{"name":"odrl-ext","kind":"hosted","media_type":"text/turtle"}'

cat > odrl-ext.ttl <<'TTL'
@prefix ex: <https://example.com/ns#> .
@prefix odrl: <http://www.w3.org/ns/odrl/2/> .
ex:access a odrl:Action .
TTL

curl -k -X PUT $HUB/v1/namespaces/demo/vocabularies/odrl-ext/content \
  -H "Authorization: Bearer $STEWARD" -H "Content-Type: text/turtle" \
  --data-binary @odrl-ext.ttl
```

The answer is revision `r1` with its digest. Uploading the same bytes again returns `200` and creates nothing; different bytes create `r2`.

A proxy vocabulary pins a copy of an upstream document:

```bash
curl -k -X POST $HUB/v1/namespaces/demo/vocabularies -H "Authorization: Bearer $STEWARD" \
  -d '{"name":"dcat-ap-context","kind":"proxy","media_type":"application/ld+json",
       "upstream":"http://127.0.0.1:8282/dcat-ap.jsonld"}'
```

Both are public at once:

```bash
curl -k -L $HUB/pub/demo/vocab/odrl-ext      # 303 to …/r/1, then the bytes
```

### 3. Create a draft

With the default `poc` compiler a draft is a JSON document. This one defines a `policy` slot whose schema admits two actions:

```bash
cat > draft-1.0.0.json <<'JSON'
{
  "version": "1.0.0",
  "profiles": ["https://127.0.0.1:8443/pub/demo/profiles/odrl/1.0.0"],
  "slots": [{"slot": "policy", "obligation": "mandatory", "applies_to": ["policy_intake"]}],
  "files": [{
    "path": "schemas/policy.schema.json",
    "media_type": "application/schema+json",
    "role": "json-schema",
    "slot": "policy",
    "applies_to": ["policy_intake"],
    "content": {
      "type": "object",
      "properties": {"action": {"enum": ["odrl:use", "ex:access"]}},
      "required": ["action"]
    }
  }]
}
JSON

curl -k -i -X POST $HUB/v1/namespaces/demo/drafts \
  -H "Authorization: Bearer $STEWARD" --data-binary @draft-1.0.0.json
```

Keep the last segment of the `Location` header as `DRAFT`. The `ETag` is needed to replace the draft later (`PUT` with `If-Match`).

### 4. Validate and propose

```bash
curl -k -X POST "$HUB/v1/namespaces/demo/drafts/$DRAFT:validate" -H "Authorization: Bearer $STEWARD"
# {"valid": true, "class": "initial", "findings": []}

curl -k -X POST "$HUB/v1/namespaces/demo/drafts/$DRAFT:propose" -H "Authorization: Bearer $STEWARD"
```

The candidate carries its `class`, the `diff` against the current head, the `lifecycle` parameters and the `planned` record with the dates it would get. Keep the last segment of its `id` as `CANDIDATE`. The candidate is frozen: editing the draft afterwards does not change it.

### 5. Approve

```bash
curl -k -X POST "$HUB/v1/namespaces/demo/candidates/$CANDIDATE:approve" \
  -H "Authorization: Bearer $STEWARD" -d '{}'
```

The answer is the signed `VersionRecord`. As an `initial` version, `new_content_from` and `enforced_from` are both the publication instant plus the propagation window (two days by default).

### 6. Read the credentials

```bash
curl -k $HUB/v1/namespaces/demo/versions          # VersionListing
curl -k $HUB/v1/namespaces/demo/versions/1.0.0    # VersionRecord
```

Each is a VC 2.0 document whose `proof` has `cryptosuite: eddsa-jcs-2022` and a `verificationMethod` under the hub DID. The listing has `sequence: 1` and a `validUntil` one `ttl` ahead; the hub re-issues it before it expires.

### 7. Read the published package

```bash
MANIFEST=$(curl -sk $HUB/v1/namespaces/demo/versions/1.0.0 | jq -r .credentialSubject.manifest)
curl -k "$HUB/pub/packages/${MANIFEST#ni:///sha-256;}/manifest.json"
curl -k -i $HUB/pub/demo/1.0.0/schemas/policy.schema.json
```

The file is served with `Cache-Control: public, max-age=31536000, immutable` and an `ETag` equal to its SHA-256.

### 8. Read the audit trail

```bash
curl -k $HUB/v1/namespaces/demo/events -H "Authorization: Bearer $STEWARD"
```

</Steps>

<Callout type="info">
`GET /pub/demo` redirects to the head version. It answers `404` until some version is in force, which for a first release means after the propagation window.
</Callout>
