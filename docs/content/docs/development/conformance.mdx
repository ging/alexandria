## 2. Running It

```bash
make conformance   # go test ./conformance/...
make e2e           # TestE2E_F6 only, verbose
make demo          # the four binaries and the F6 verdict table
make trace         # regenerate and verify TRACEABILITY.md
```

`T-*` tests live next to the code they exercise; `conformance/` holds the cross-cutting ones: the negative corpus, the determinism check and the end-to-end scenario.

---

## 3. Scenario F6

F6 follows one namespace over two and a half months:

1. `1.0.0` is published (`initial`) and takes effect after the propagation window.
2. `2.0.0` (`breaking`) removes a policy action and opens a grace window.
3. During the grace window, a message valid only under `1.0.0` is forwarded with a `VHub-Verdict` warning that names the sunset instant.
4. After `enforced_from` plus the lease margin, the same message is rejected.
5. An agreement captured under `1.0.0` keeps admitting transfers until `1.0.0` is revoked and the revocation takes effect.

All processes read the same file clock (`-clock-file`), so the whole timeline replays in seconds and gives the same table on every run.

## 4. Traceability Matrix

`make trace` runs `conformance/trace`, which regenerates [`TRACEABILITY.md`](https://github.com/ging/alexandria/blob/main/TRACEABILITY.md) and fails unless:

- every requirement maps to at least one module and one `T-*` test,
- every production package declares the requirements it implements, and
- every reachable catalog code has its negative case.

Packages declare their requirements in the two-line header comment of each file, which is where the generator reads them.
