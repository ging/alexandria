# Conformance & Traceability Suite

Alexandria enforces conformance at two complementary levels:
1. **Dataspace Payload Conformance:** Validating Connector DSP messages, ODRL offers/agreements, and DCAT catalog datasets against compiled JSON Schema Draft 2020-12 (`schema.json`) and W3C SHACL (`shapes.ttl`) artifacts.
2. **System Conformance & Traceability (`conformance/`):** An automated verification suite proving that `alexandria-server`, `alexandria-client`, and `alexandriac` satisfy all **61 normative requirements (`REQ-*`)**, the **64-code closed error catalog (`F5`)**, and the **End-to-End Scenario F6**.

---

## 2. Running the Conformance Battery

<Steps>

### 1. Run Unit, Contract & Architecture Tests

```bash
make test
```
Executes all tests under `./internal/...` and `./cmd/...`, including `internal/archtest` (Hexagonal boundaries, `DP-1` dependency allowlist, and `DP-9` no-`time.Now()` AST check) and all `TestT_SYS_*`, `TestT_HUB_*`, and `TestT_CLI_*` tests.

### 2. Run the Full `conformance/` Suite

```bash
make conformance
```
This runs:
- **`conformance/documents_test.go` (`T-DOC-001`..`004`, `T-SYS-005`..`006`):** Validates real binary outputs against the normative Appendix A JSON Schemas (`conformance/schemas/*.schema.json`) and verifies byte immutability on `/pub`.
- **`conformance/determinism_test.go`:** Verifies that two independent `alexandria-client` instances given the same listing and clock produce identical classifications and headers across all inputs (`REQ-SYS-001`).
- **`conformance/negative_hub_test.go`:** Executes negative `TestN_<CODE>` tests for every `C-HUB` error code (`API_*`, `RELEASE_ABORTED`, `DATES_*`, `LIFECYCLE_*`) using the negative draft corpus in `conformance/corpus/drafts/`.
- **`conformance/negative_client_test.go`:** Executes negative `TestN_<CODE>` tests for every `C-CLI` error code (`CONFIG_*` in `conformance/corpus/config/`, `SYNC_*`, `DID_*`, `CLIENT_*`, `VERDICT_*`, `AGREEMENT_*`, `AUDIT_*`, `CLOCK_SKEW_EXCEEDED`).
- **`conformance/e2e_f6_test.go` (`TestE2E_F6`):** Launches the real binaries and verifies all 19 rows of Scenario F6.

### 3. Regenerate & Verify `TRACEABILITY.md`

```bash
make trace
```
Runs `go run ./conformance/trace`, which parses Go test functions (`TestT_*`, `TestN_*`), package requirement annotations, and `internal/core/codes/catalog.tsv`, failing if any requirement or reachable catalog code lacks test coverage, and writes `TRACEABILITY.md`.

</Steps>

## 3. Normative Schemas & Corpus (`conformance/`)

```text
conformance/
├── corpus/
│   ├── config/             # Invalid client configs triggering CONFIG_SCHEMA, CONFIG_ROUTE_OVERLAP, etc.
│   └── drafts/             # Invalid drafts triggering LIFECYCLE_CLOCK_SKEW, LIFECYCLE_GRACE_ZERO, etc.
├── demo/                   # CLI runner for make demo (prints F6 verdict table)
├── examples/               # Normative JSON examples (config.json, version.json, versions.json, verdict-event.json)
├── f6/                     # Scenario F6 YAML drafts (v1.0.0.yaml, v2.0.0.yaml), process launcher & driver
├── schemas/                # Appendix A JSON Schemas (Draft 2020-12):
│   ├── config.schema.json          # Appendix A.3: alexandria-client configuration
│   ├── verdict-event.schema.json   # Appendix A.4: structured verdict events
│   ├── version.schema.json         # Appendix A.2: eunomia.version/v1 record
│   └── versions.schema.json        # Appendix A.1: eunomia.versions/v1 listing
└── trace/                  # Automated TRACEABILITY.md generator & verifier
```
