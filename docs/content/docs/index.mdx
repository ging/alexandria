# Alexandria Documentation

Welcome to the **Alexandria** documentation portal. Alexandria is a **Vocabulary Hub and Sovereign Identity Ecosystem** engineered to deliver semantic interoperability, profile compilation, runtime term dereferencing, edge DSP traffic validation, and delegated cryptographic trust for modern dataspaces.

<Callout type="info">
Alexandria combines two complementary planes in a single Go repository:
1. **Vocabulary Hub & Edge Sidecar (`alexandria-server`, `alexandria-client`, `alexandriac`):** Complete reference implementation of the *Vocabulary Hub v0.2.1* specification and the `eunomia.profiles/v1` YAML profile language.
2. **Identity, SSI & Auth Gateway (`cmd/alexandria`):** Decentralized Identity (`did:web` / `did:jwk`), unified external wallet management (**Fafnir** and **Eclipse EDC IdentityHub**), DCP credential flows, and node-terminated **Zitadel** OIDC authentication.
</Callout>

---

## Core Capabilities

1. **Profile Language & Deterministic Compiler (`alexandriac`):** Author ODRL policy profiles (`OdrlProfile`) and dataspace governance bindings (`SpaceProfile`) in YAML (`eunomia.profiles/v1`). Automatically validate across 5 normative levels (`N1`–`N5`) and generate `vocab.ttl`, `context.jsonld`, `shapes.ttl`, `schema.json`, `cedar.schema`, `prof.ttl`, `spec.html`, and `space-lock.json`.
2. **Vocabulary Hub Server (`alexandria-server`):** Authoring, candidate proposal, multi-role release approval (`editor`, `releaser`, `member`), lifecycle window calculation (`published_at`, `new_content_from`, `enforced_from`, `revoked_from`), JCS + Ed25519 cryptographic signing, SQLite immutability triggers, and content-addressed `/pub` distribution.
3. **Edge Validation & Sync Sidecar (`alexandria-client`):** Zero-hub-latency L7 Dataspace Protocol (DSP) reverse and forward proxy. Continuously synchronizes and verifies signed listings (`S1`–`S13`), enforces policy and schema gates (`observe`, `shadow`, `enforce`), attaches RFC 9651 `VHub-Verdict` headers, and tracks active contract agreements across version transitions and revocations.
4. **Sovereign Identity & Unified Wallet Port (`alexandria`):** Cryptographic keys never reside in the application node. Key custody, DID lifecycle, service endpoints, participant contexts, OID4VCI/OID4VP, and DCP requests are delegated via `wallet.Wallet` to **Fafnir** or **Eclipse EDC IdentityHub**, guarded by **Zitadel** OIDC + PKCE.
