# Vocabulary Hub (`vhub`) — Specification v0.3.0

Alexandria implements the **Vocabulary Hub specification v0.3.0** (parts F2–F8, Appendices A–C): 81 normative requirements and a closed catalog of 77 codes.

Two guarantees shape the design:

1. **Determinism (`REQ-SYS-001`).** The same rules, packages, listing, message and instant always give the same classification, action and codes, on any client.
2. **No hub on the request path (`REQ-SYS-002`).** The client decides on a message using only local, already verified state. Synchronization and DID resolution happen in the background.

## Core Concepts

| Concept | Meaning |
|:---|:---|
| **Namespace** | Unit of isolation in the hub: its own stewards, vocabularies, releases, events and listing sequence. The slug `_vhub` is reserved. |
| **Admin / steward** | The admin (a token role) creates namespaces and assigns stewards. Stewards (principals `iss` + `sub`) operate inside their namespace. |
| **Vocabulary** | A `hosted` document uploaded to the hub or a `proxy` copy of an upstream, stored as immutable revisions. |
| **Draft → candidate → version** | A draft is editable. Proposing it freezes a candidate. Approving the candidate publishes a version. |
| **Release class** | `initial`, `compatible` or `breaking`, derived from the SemVer increment. |
| **Lifecycle dates** | `published_at`, `new_content_from`, `enforced_from` and, after revocation, `revoked_from`. Once emitted they never change. |
| **Credentials** | `VersionListing`, `VersionRecord` and `PackageManifest`: VC 2.0 documents with an `eddsa-jcs-2022` proof. |
| **Rule** | Client-side mapping from listener, method and path to gates and a mode. |
| **Gate** | Validation point: `dsp_message`, `policy_intake`, `catalog_entry` or `agreement_admission`. |
| **Mode** | `observe` (silent), `shadow` (events only) or `enforce` (may reject). |

## Shared Core (`internal/core`)

Both binaries build on a pure, network-free core:

| Package | Responsibility |
|:---|:---|
| `timex` | Instants, ISO 8601 durations and the injectable `Clock` port (`DP-8`). |
| `semver` | SemVer 2.0 parsing and ordering. |
| `canon` | RFC 8785 JSON Canonicalization Scheme. |
| `ni` | RFC 6920 `ni:///sha-256;…` digests. |
| `did` | `did:key` and `did:web` parsing and DID document checks. |
| `vc` | VC 2.0 credentials with Data Integrity `eddsa-jcs-2022` proofs (`DP-3`). |
| `lifecycle` | Date planning, approval and revocation invariants, in-force computation and reference states. |
| `pkgv` | Package verification: manifest, digests and file-set completeness. |
| `codes`, `problem` | The closed catalog and RFC 9457 problem documents. |
| `schemas` | Embedded JSON Schemas of Appendix A and the A.5 context. |
| `jsonld` | Offline JSON-LD 1.1 expansion; the document loader never touches the network. |
| `logx` | Structured logging helpers that attach catalog codes. |
