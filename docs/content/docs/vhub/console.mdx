# Alexandria Console

If you prefer clicking, dragging, and seeing live diffs over crafting raw `curl` commands, the **Alexandria Console** gives both binaries a single, unified browser interface.

Every release workflow (`draft → validate → propose → approve → publish → revoke`), hosted or proxy vocabulary management, live `/pub` artifact browsing, client synchronization (`Sync now`), rule editing (`Policy path`), and DSP dry-run testing (`Explain`) happens right inside the console.

---

## Launching the Console

You can open the console in two ways:

| Mode | How to start | URL | Workspaces shown |
|:---|:---|:---|:---|
| **Embedded (`/ui/`)** | Build with `make build-gui`, then run `alexandria-server` and `alexandria-client` | `https://127.0.0.1:8443/ui/` (Hub) · `http://127.0.0.1:9090/ui/` (Client) | One per binary (`Server` or `Client`) |
| **Development (`make gui-dev`)** | Run `alexandria-server`, `alexandria-client`, and `make gui-dev` | `http://localhost:5273/` | **Both** (`Server ↔ Client` switcher in top bar) |

---

## Signing In & Trusting the Hub

1. Click **Anonymous** in the top-right header to open the **Identity** dialog.
2. In a local lab (`fake-idp`), use **Sign in with OIDC** (Authorization Code + PKCE) for one-click sign-in as `ana · admin` or `sergio · steward`—or paste any JWT on the **Access token** tab.
3. Need the Hub's public identity for an `alexandria-client` configuration? Open any namespace and copy the **Hub DID** badge at the bottom of the left sidebar (or in **Overview**) with one click.

## Hub Governance Workspace (`Server`)

| View | Shortcut | What you can do here |
|:---|:---:|:---|
| **Namespaces** | `g n` | List dataspace namespaces and create new ones (requires `vhub-admin`). |
| **Overview** | `g o` | Inspect namespace summary, copy **Hub DID**, view active head version, and assign or remove stewards. |
| **Vocabularies** | `g v` | Register `hosted` vocabularies (upload Turtle / JSON-LD revisions) or `proxy` upstreams and inspect immutable revision bytes. |
| **Authoring Studio** | `g a` | Press `n` for the full-height **New draft** editor. Switch between **Form**, **Split** (live Form ↔ YAML sync), and **Code** (`f` / `s` / `y`), switch **ODRL Profile ↔ Space Profile** (`1` / `2`), run `N1–N5` validation (`⌘↵`), save (`⌘S`), propose candidates, browse compiled files (`vocab.ttl`, `schema.json`, `shapes.ttl`, rendered `spec.html`) and inline diffs, then **Approve & publish** or **Reject**. |
| **Versions** | `g l` | Inspect signed `VersionRecord` entries, active dates (`new_content_from`, `enforced_from`), compiled artifacts, or schedule a justified revocation. |
| **Publication (`/pub`)** | `g p` | Interactive tree explorer for every public immutable URL under `/pub/{ns}/...`—including live rendered `spec.html` previews and HTTP cache/ETag headers. |
| **Events** | `g e` | Inspect the append-only namespace or hub-wide audit trail. |

## Edge Validation Workspace (`Client`)

| View | Shortcut | What you can do here |
|:---|:---:|:---|
| **Status** | `g s` | Watch the sidecar state machine (`Onboarding → Active ↔ Transition → Degraded / FailClosed`), hub continuity sequence, `/readyz` readiness, and trigger an immediate sync with **Sync now** (`r`). |
| **Versions** | `g c` | Inspect synchronized lifecycle versions (`Published`, `Scheduled`, `Deprecated`, `Revoked`), effective dates, and cached package digests. |
| **Rules** | `g u` | View or edit forwarding/enforcement rules, modes (`observe` vs `enforce`), gate lists (`dsp_message`, `policy_intake`, `catalog_entry`), and **Policy path (`verify.select`)** JSON pointers such as `/offer`. |
| **Explain** | `g x` | Dry-run any DSP message against local rules without touching the upstream connector. Click a rule chip (`contract-request`, `contract-offer`, etc.) to populate canonical **DSP 2025-1-err2** payloads and press `⌘↵` to inspect gate-by-gate findings and response headers (`VHub-Verdict`). |
| **Agreements** | `g g` | Inspect captured agreements pinned to their originating profile version and check whether a scheduled revocation threatens any active transfer. |
| **Audit & Metrics** | `g t` / `g m` | Review passive `catalog_entry` audit violations and inspect live OpenMetrics exposition. |

## Keyboard-First Workflow

Alexandria Console is built so you barely need to reach for your mouse. Press **`?`** anywhere (outside a text input or CodeMirror editor) to view the live shortcut cheatsheet, or see it in action below:

| Scope | Keys | Action |
|:---|:---:|:---|
| **Global** | `⌘K` / `Ctrl+K` | Open **Command palette** to jump to any page or action |
| | `?` | Open / close **Keyboard shortcuts** guide |
| | `/` | Focus the current table filter or `/pub` path bar |
| | `Esc` | Close active detail drawer, dialog, or clear active filter |
| | `g w` | Switch **Server ↔ Client** workspace (when both are mounted) |
| **Server Go-to** | `g n` · `g p` · `g o` · `g v` · `g a` · `g l` · `g e` | Namespaces · Publication · Overview · Vocabularies · Authoring · Versions · Events |
| **Client Go-to** | `g s` · `g c` · `g u` · `g x` · `g g` · `g t` · `g m` | Status · Versions · Rules · Explain · Agreements · Audit · Metrics |
| **Workspaces** | `↑` / `↓` (or `j` / `k`) · `Enter` | Move through table rows and open the detail drawer |
| | `[` | Collapse / expand draft list or `/pub` file tree rail |
| | `n` | Open inline full-height **New draft** (Authoring) |
| | `1` / `2` | Switch **ODRL Profile ↔ Space Profile** (Authoring Studio) or result tabs (Explain) |
| | `f` / `s` / `y` | Switch Studio mode: **Form** / **Split** / **Code** |
| | `⌘S` / `Ctrl+S` | Save current draft |
| | `⌘↵` / `Ctrl+↵` | Validate draft · Create draft · Run Explain |
| | `r` | Trigger **Sync now** (`POST /sync`) on Status / Versions |
