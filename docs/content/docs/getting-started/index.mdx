# Alexandria: The Vocabulary Hub Ecosystem

**Alexandria** is a sovereign dataspace **Vocabulary Hub** and **Identity Gateway**. It enables dataspace authorities to author and govern semantic profiles in YAML, distribute cryptographically signed vocabulary packages, validate Dataspace Protocol (DSP) traffic at the connector edge without runtime network latency, and manage decentralized identities (DIDs) and verifiable credentials.

---

## Core Binaries & Components

The repository provides four main entrypoints under `cmd/` and `deploy/`:

| Binary | Source | Role in the Dataspace |
|:---|:---|:---|
| **`alexandriac`** | `cmd/alexandriac` | **Profile Language Compiler CLI:** Validates `eunomia.profiles/v1` YAML documents (`OdrlProfile`, `SpaceProfile`) across N1–N5 and deterministically compiles RDF/OWL/SKOS, JSON-LD `@context`, SHACL shapes, JSON Schema Draft 2020-12, Cedar schemas, W3C PROF, HTML specs, and `space-lock.json`. |
| **`alexandria-server`** | `cmd/alexandria-server` | **Vocabulary Hub Server (`C-HUB`):** Exposes `/v1` governance APIs (drafts, candidates, releases, revocations, events), signs `eunomia.versions/v1` listings with Ed25519 over JCS, serves `/.well-known/did.json`, and publishes immutable content-addressed artifacts under `/pub/`. |
| **`alexandria-client`** | `cmd/alexandria-client` | **Edge Validation & Sync Sidecar (`C-CLI`):** Runs alongside a dataspace Connector. Synchronizes and verifies signed packages in the background (`S1`–`S13`), proxies DSP ingress/egress traffic (`observe`, `shadow`, `enforce`), emits `VHub-Verdict` headers, tracks contract agreements, and exposes a local Admin & Prometheus metrics API. |
| **`alexandria`** | `cmd/alexandria` | **Identity, SSI & Auth Gateway:** Modular monolith providing node-terminated **Zitadel** OIDC + PKCE login, interactive Swagger UI (`/docs`), and the unified `wallet.Wallet` REST API (`/api/v1/wallet/*`) backed by **Fafnir** or **Eclipse EDC IdentityHub**. |

## How the Pieces Fit Together

### 1. Authoring & Governance (`alexandriac` + `alexandria-server`)
A dataspace authority defines allowed policy actions, constraints, and slot bindings in YAML (`eunomia.profiles/v1`). When proposed and approved on `alexandria-server`, the Hub compiles the deterministic artifacts, calculates lifecycle transition dates (`published_at`, `new_content_from`, `enforced_from`), registers a transparency receipt, and signs the version listing (`eunomia.versions/v1`) with its Ed25519 key published at `/.well-known/did.json`.

### 2. Edge Synchronization & Zero-Latency Enforcement (`alexandria-client`)
Each participant runs `alexandria-client` as a sidecar proxy in front of their Dataspace Connector:
- **Background Sync Loop:** Periodically polls `GET /v1/versions`, verifies the Hub's `did:web` key, checks anti-rollback continuity (`S1`–`S13`), and downloads content-addressed PVP packages (`ni:///sha-256;...`) to local disk.
- **Hot-Path L7 Proxy:** Intercepts inbound and outbound DSP messages (`ContractRequestMessage`, `ContractAgreementMessage`, `TransferRequestMessage`, `CatalogRequestMessage`) and evaluates them strictly against local verified packages—**never contacting the Hub on the request path** (`REQ-SYS-002`).
- **Graceful Version Transitions:** During a breaking release's transition window, offers using deprecated/retired terms from the previous version are forwarded with an RFC 9651 `VHub-Verdict: warning;gate=policy_intake;code="VERDICT_NOT_IN_HEAD";sunset=...` header, and only rejected after `enforced_from + lease_margin`.

### 3. Decentralized Identity & Delegated Wallets (`alexandria`)
Through `internal/ssi-auth` and `internal/auth-proxy`, Alexandria delegates private key storage, DID document management, W3C Verifiable Credential storage, OID4VCI/OID4VP flows, and DCP credential requests to external wallets (**Fafnir** or **Eclipse EDC IdentityHub**), while protecting management APIs with **Zitadel** OIDC sessions.
