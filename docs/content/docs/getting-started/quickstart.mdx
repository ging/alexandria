# Quickstart

---

## Path A: Build, Test and Run the F6 Demo

<Steps>

### 1. Build the binaries

```bash
make build
```

Produces `bin/alexandria-server`, `bin/alexandria-client`, `bin/alexandriac`, `bin/fake-idp` and `bin/fake-connector`.

### 2. Run the suites

```bash
make test conformance e2e trace
```

Unit and architecture tests, the conformance battery, the end-to-end F6 scenario across the real binaries, and the traceability check (81 of 81 requirements, 76 of 77 catalog codes).

### 3. Replay F6

```bash
make demo
```

Starts `fake-idp`, `fake-connector`, the server and the client with a shared file clock, replays two and a half months of lifecycle in seconds and prints the verdict table: the same messages moving through `ok`, `warning` with a `VHub-Verdict` notice, and `violation` as versions are published, enforced and revoked.

</Steps>

## Path B: Start the Laboratory by Hand

<Steps>

### 1. Start the services

Each command in its own terminal, from the repository root:

```bash
./bin/fake-idp serve
./bin/fake-connector
./bin/alexandria-server -config config/server.yaml
./bin/alexandria-client -config config/client.yaml
```

On first start the server creates its signing key and a laboratory TLS certificate under `var/`, and logs its `hub_did`. Copy that DID into `did_config.hub_did` of `config/client.yaml` before starting the client: the client only accepts credentials issued by the DID it is configured to trust.

### 2. Get tokens

```bash
ADMIN=$(./bin/fake-idp token --sub ana --admin --ttl 24h)
STEWARD=$(./bin/fake-idp token --sub sergio --ttl 24h)
```

### 3. Create a namespace and a steward

```bash
curl -k -X POST https://127.0.0.1:8443/v1/namespaces \
  -H "Authorization: Bearer $ADMIN" \
  -d '{"slug":"demo","title":"Demo data space"}'

curl -k -X POST https://127.0.0.1:8443/v1/namespaces/demo/stewards \
  -H "Authorization: Bearer $ADMIN" \
  -d '{"iss":"http://127.0.0.1:9400","sub":"sergio","label":"Sergio"}'
```

### 4. Check both sides

```bash
curl -k https://127.0.0.1:8443/v1/namespaces
curl http://127.0.0.1:9090/status
```

The client reports `Onboarding` until the namespace publishes its first version.

</Steps>

<Callout type="info">
Prefer a browser? `make build-gui` embeds the **[Alexandria Console](../vhub/console)** in both binaries (`/ui/`), and `fake-idp serve` provides a password-less sign-in page for the lab admin and stewards.
</Callout>

<Callout type="info">
Continue with the **[tutorials](../tutorials)** to publish a release and send DSP traffic through the proxy.
</Callout>

## Command Cheat Sheet

| Action | Command |
|:---|:---|
| Build the binaries | `make build` |
| Build with the embedded console | `make build-gui` |
| Unit, contract and architecture tests | `make test` |
| Conformance battery | `make conformance` |
| End-to-end F6 scenario | `make e2e` |
| F6 demo table | `make demo` |
| Traceability matrix | `make trace` |
| Format, lint, test, conformance and trace | `make check` |
| Console development server | `make gui-dev` |
| Jupyter tutorials | `make tutorial` |
| Documentation site | `make docs-dev` |

Every target has a `task` equivalent (`task build`, `task build:gui`, `task gui:dev`, …).
