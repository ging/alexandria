# Quickstart Guide

Alexandria offers two quickstart paths depending on whether you want to explore the **Vocabulary Hub & Edge Validation Sidecar (`vhub`)** or the **Full Identity, OIDC & External Wallet Stack (`cmd/alexandria`)**.

---

## Path A: Vocabulary Hub & Edge Sidecar in 3 Commands (`Makefile`)

You can compile the Vocabulary Hub binaries, run the full conformance battery, and execute the end-to-end **Scenario F6** (which launches real `alexandria-server`, `alexandria-client`, and `fake-connector` processes and replays a two-month vocabulary lifecycle in seconds) with zero container dependencies:

<Steps>

### 1. Build the Binaries and DSL Compiler

Compile `bin/alexandria-server`, `bin/alexandria-client`, `bin/fake-connector`, and `bin/alexandriac`:

```bash
make build
go build -o bin/alexandriac ./cmd/alexandriac
```

### 2. Compile a YAML Profile with `alexandriac`

Validate and compile the sample `colors.profile.yaml` (`eunomia.profiles/v1`) into RDF/Turtle, JSON-LD `@context`, SHACL shapes, JSON Schema, Cedar policy mappings, and HTML documentation:

```bash
./bin/alexandriac validate internal/dsl/testdata/colors.profile.yaml
./bin/alexandriac compile -o /tmp/colors-out internal/dsl/testdata/colors.profile.yaml
```

### 3. Run the End-to-End F6 Demo

Run `make demo` to spin up `alexandria-server`, `alexandria-client`, and `fake-connector` with a shared injectable clock, publish releases `1.0.0` and `2.0.0` from YAML bundles, and print the live verdict table:

```bash
make demo
```

You will see the complete chronological table of DSP messages (`m1 odrl:use`, `m2 ex:access`, `m3 odrl:read`, `A1 agreement`, `A1 transfer`, and `revoke 1.0.0`) transitioning across `ok (forward)`, `warning (forward-notice)`, and `violation (reject)`:

Verify all 61 normative requirements (`REQ-*`) and 63 negative catalog codes (`N-*`):


## Path B: Full Identity, OIDC & Wallet Stack (`Taskfile`)

For developing with `cmd/alexandria`, Zitadel OIDC, Caddy TLS, PostgreSQL, and external wallets (**Fafnir** or **Eclipse EDC IdentityHub**), use `task dev:auto`:

```bash
# 1. On a fresh machine, trust the local CA once (requires sudo):
task tls:trust

# 2. Start the full stack with automatic orchestration:
task dev:auto
```

`task dev:auto` automatically:
1. Generates and verifies the root Certificate Authority (CA) in `/.certs/`.
2. Frees internal port `1234` if held by a stale process.
3. Starts Docker containers (`postgres`, `caddy`, `zitadel`, `fafnir-wallet`).
4. Runs `scripts/zitadel-bootstrap.sh` to provision OIDC clients and populate `.env`.
5. Runs `scripts/fafnir-bootstrap.sh` to provision the default Ed25519 key and DID.
6. Starts `cmd/alexandria` with live reload via `air`.

## Alternative Wallet Configurations

<Tabs items={['Eclipse EDC IdentityHub', 'Fafnir with HashiCorp Vault']}>

<Tab value="Eclipse EDC IdentityHub">

Alexandria supports **Eclipse EDC IdentityHub** (including participant management, JWK/PEM keypairs, VC 1.0/2.0 normalization, and DCP credential requests):

```bash
# 1. Start the IdentityHub container on ports 8181 and 8182:
task identityhub:up

# 2. Launch Alexandria pointing to IdentityHub (or use config/config-ih.yaml):
ALEXANDRIA_WALLET_CONFIG_WALLET=IdentityHub \
ALEXANDRIA_WALLET_CONFIG_API_HTTP_PORT=8181 \
task dev
```

To stop IdentityHub: `task identityhub:down`.

</Tab>

<Tab value="Fafnir with HashiCorp Vault">

By default, Fafnir stores keys on a Docker volume. To run Fafnir backed by **HashiCorp Vault**:

```bash
# 1. Start Vault and seed root tokens:
task vault:up

# 2. Provision the wallet identity inside Vault:
task wallet:bootstrap

# 3. Start Alexandria:
task dev
```

Vault UI is available at `http://127.0.0.1:8200` with root token `alexandria-dev-root`. To return Fafnir to file storage: `task vault:down`.

</Tab>

</Tabs>

## Verifying the Identity & API Stack

Once `task dev:auto` is running, verify the endpoints:

### 1. Interactive Swagger / OpenAPI UI
Open the built-in Swagger UI in your browser:
```text
https://alexandria.127.0.0.1.nip.io:8443/docs
```
Raw specifications are served at `/openapi.json` and `/openapi.yaml`.

### 2. Web Portal & Authentication Login
Navigate to:
```text
https://alexandria.127.0.0.1.nip.io:8443/api/v1/auth/login
```
Log in using:
- **Username:** `admin@alexandria.auth.127.0.0.1.nip.io`
- **Password:** `Password1!`

### 3. DID Document & Health Probes
```bash
curl -k https://alexandria.127.0.0.1.nip.io:8443/.well-known/did.json
curl -k https://alexandria.127.0.0.1.nip.io:8443/healthz
curl -k https://alexandria.127.0.0.1.nip.io:8443/readyz
```

## Operational Cheat Sheet

| Action | Command |
|:---|:---|
| **Build `vhub` binaries** | `make build` |
| **Run F6 interactive demo** | `make demo` |
| **Run conformance & traceability** | `make conformance trace` |
| **Start full SSI stack (`alexandria`)** | `task dev:auto` |
| **Start local Fumadocs server** | `task docs:dev` |
| **View Caddy / Zitadel / Wallet logs** | `task tls:logs` / `task auth:logs` / `task wallet:logs` |
| **Open Postgres Shell** | `task db:psql` |
| **Open Zitadel Console** | `task auth:console` |
| **Reset Database / Auth / Wallet** | `task db:reset` / `task auth:reset` / `task wallet:reset` |
